# Graphics callback contract

`set_graphics_callbacks(GraphicsCallbacks)` exposes an optional host seam. Registration requires active observation, which the retail proxy enables only after the full SP file/loaded-PE identity guard and `BOVR_INSTRUMENT=1`. The default callback table is empty and starts no XR work. Tests enable observation explicitly inside their own synthetic process.

- `before_present(context, borrowed_device)` runs only before implicit swap-chain 0's original Present. DevicePresent/PresentEx provide a thread-local outer-call scope but never invoke capture themselves. Nested or reentrant presentation invokes the callback at most once within that outer call; independent swap-chain Present calls remain independent. Additional chains are excluded. `GetDevice` contributes one transient reference, released after the callback even if it throws. If the retail engine bypasses the observed swap-chain method, this seam does not run; trace the actual path before wiring VR.
- `before_reset(context, device)` must retire the host's graphics ownership on its permitted thread. False or exception skips the real Reset/ResetEx and returns `D3DERR_DEVICELOST`. `D3DERR_WASSTILLDRAWING` is not used as a Reset result. The denied attempt performs no device query, clears no swap association, and invokes no after-reset callback. The host must arrange owner-thread progress rather than blindly retrying a blocked foreign-thread call.
- `after_reset(context, device, hr)` runs only after an admitted real reset, with its actual HRESULT. The callback is responsible for calling the coordinator's matching after-reset path. On a failed real reset, the observer performs no further device calls; after success it reacquires implicit swap-chain 0. A callback exception is logged and cannot replace the original HRESULT. The host must track whether the device was already lost; the observer does not infer runtime ownership or marshal threads.
- `device_released(context, dead_identity)` runs after a tracked device's real Release returns zero. It receives an opaque integer, never a usable COM pointer. It may run on any release thread and must only publish metadata. The root adapter must keep its explicit owner reference until XR/GPU retirement succeeds on the owner thread, then unbind and release. Final Release notification is too late for graphics cleanup.

No observer lock spans a COM method or callback. A callback snapshot pins the caller's context contract: replacement or unbinding fails while any snapshot is in flight. Retry unbinding from outside callbacks and preserve the context until it succeeds. Callback exceptions are contained at the ABI boundary. Untracked devices that share driver vtables keep ordinary reset behavior.

The independent `BOVR_BACKEND_PROBE=1` startup probe is integrated beside the scene probe. Its six-byte entry patch relocates `push ebp; mov ebp,esp; and esp,-8` into an eleven-byte trampoline and jumps back to `entry+6`. A synthetic executable test verifies wrong-byte rejection, opt-in behavior, exact once-only execution, stack restoration and idempotent installation without loading a retail executable. It does not prove the retail function's semantic mapping or runtime timing.

`graphics_callback_contract` covers nested/reentrant Present, default no-op forwarding, balanced references, additional-chain exclusion, failed GetDevice, throwing callbacks, context unbind refusal, owner-thread reset denial, native ResetEx, shared-vtable isolation and final device destruction. No live VR function is registered by this module.
