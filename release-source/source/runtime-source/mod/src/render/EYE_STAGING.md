# Per-eye pixel staging (V5 experimental world probe)

The retail V4 run in `phase3/evidence/stereo-v4-01` submitted matching frontend/backend frame identities but the left eye was black (`kino-first-eyes.jpg`). Its second native view cleared shared render targets. Matching completion metadata did not preserve the first eye's pixels.

`EyeStaging` saves each completed eye's exact backbuffer rectangle into its own default-pool render target immediately after the corresponding native `RB_Draw3D` returns. It requires left then right under one nonzero producer serial, disjoint in-bounds rectangles, the same render-owner thread/device and unchanged dimensions/format. The adapter marks an eye complete only after its copy succeeds. At the authoritative swap-chain pre-Present callback, the exact producer's two saved rectangles are restored immediately before the existing coordinator captures the backbuffer. The pair is consumed on restoration and cannot replay.

This world-only probe intentionally replaces later native overlays inside the eye rectangles. Menu/HUD composition must be implemented deliberately; V5 does not claim usable stereo menus or final HUD. Native full-screen overlays cannot erase the saved world pair before capture. Copy failure or stale ownership discards the XR frame. Multisampled backbuffers are rejected because restoration into a multisampled destination is not a supported resolve direction. The helper never changes render targets, viewport, scissors, shaders, or BeginScene/EndScene balance. Its resources retire on the render owner before reset and normal quit, ahead of device release.

The Microsoft color render-target copy contract is documented at [IDirect3DDevice9::StretchRect](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-stretchrect). Driver support varies; this implementation uses equal-format, equal-size non-multisampled default-pool render targets and checks every HRESULT. It does not perform depth/stencil copies.

`bovr-eye-staging-probe --hidden-device` is an explicit local GPU test, excluded from CTest. It loads the system D3D9 library, creates a hidden Ex device, and checks 240 frame-coded red/blue pairs across two sizes. Half run inside BeginScene/EndScene. Each eye sequence includes a whole-target clear between eyes and another whole-target overwrite before restoration. Two negative controls read back the uncorrected buffer and confirm the original left image really was erased. Final readbacks compare 1,536,000 pixels against the current producer. The test also rejects missing/duplicate/reordered eyes, wrong producer, invalid rectangles, consumed pairs and foreign threads; preserves native viewport/scissor/target state; and tests ResetEx plus zero remaining device references after explicit retirement.

Recorded offline evidence: `mod/eye-staging-build.log` (11/11 CTests), `mod/eye-staging-probe-02.log` (4,820 checks, no failures). This is graphics-component evidence; the source assumption that native Draw3D's returned backbuffer contains the final eye still requires the separate V5 retail probe.
